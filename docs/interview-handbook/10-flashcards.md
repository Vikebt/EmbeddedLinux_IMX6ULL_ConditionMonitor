## 1. 使用方式

速记卡不是正文的替代品。正面问题能在 30 秒内回答后，还要随机抽取“反问”与“证据”两列；说不出代码位置或验证边界，就回到对应章节和实验。

## 2. C/C++ 与内存

| 正面 | 30 秒答案核心 | 反问 | 项目锚点 |
| --- | --- | --- | --- |
| `const` 有什么用 | 建立只读接口契约；顶层/底层 const 不同；可通过其他别名改变并不矛盾 | const 对象一定放只读段吗 | P4/P5 参数接口，01章 |
| `volatile` 能保证线程安全吗 | 不能；只约束可观察访问，缺少原子性和 happens-before | 何时会同时看到 volatile 与中断 | STM32 寄存器、ISR 标志 |
| atomic 与 mutex 怎么选 | 单个独立状态可 atomic；多个字段要保持不变量时用 mutex | memory order 用的是什么 | P4 stop flag 与 snapshot |
| 栈和堆本质区别 | 生命周期/所有权/分配机制不同，不用“一定快慢”绝对化 | RTOS 任务栈如何估算 | P1/P2 静态任务资源 |
| malloc/free 与 new/delete | 前者分配字节，后者参与对象构造析构；必须成对 | placement new 是什么 | Linux C++ RAII |
| 内存泄漏如何定位 | 最小复现、观察资源增长、ASan/Valgrind、回归测试 | fd 泄漏算内存泄漏吗 | P3/P4/P5 生命周期 |
| 野指针和悬空指针 | 未初始化或已失效地址；关键是所有权与失效时机 | shared_ptr 能完全避免吗 | P3 队列关闭、P4 join |
| RAII 是什么 | 资源绑定对象生命周期，构造获取、析构释放 | 构造中途失败怎么办 | P3 socket，P5 UniqueFd |
| 拷贝与移动区别 | 拷贝复制资源，移动转移所有权并保持源可析构 | `std::move` 会移动吗 | P3/P4 消息传递 |
| vector 扩容影响 | 重新分配并移动/拷贝，迭代器和指针可能失效 | 如何减少抖动 | 点云/帧缓存 reserve |
| lambda 捕获风险 | 引用捕获的生命周期必须覆盖异步执行 | `[=]` 捕获 this 吗 | P4 工作线程 |
| C++11 对项目最有用什么 | thread/atomic/mutex/condition_variable、移动、智能指针 | 为什么 P5 用 C++14 | 工具链兼容边界 |

## 3. ARM、ISR 与 FreeRTOS

| 正面 | 30 秒答案核心 | 反问 | 项目锚点 |
| --- | --- | --- | --- |
| 中断发生时做什么 | 保存必要现场、查向量、执行 ISR、恢复；具体由架构和编译器配合 | 嵌套中断条件 | P2 USART ISR |
| ISR 为什么要短 | 高优先级执行会推迟任务和低优先级中断，且可用 API 受限 | 能在 ISR 打日志吗 | P1/P2 ISR 边界 |
| ISR 如何唤醒任务 | 用 `...FromISR` API，必要时请求退出中断后调度 | 为什么不能用普通 queue API | P2 帧就绪通知 |
| 优先级反转是什么 | 低优先级持锁阻塞高优先级，中优先级又抢占低优先级 | mutex 如何缓解 | P1 总线互斥 |
| semaphore 与 mutex 区别 | semaphore 表示数量/事件；mutex 表示所有权并可有优先级继承 | ISR 能 give mutex 吗 | P1/P2 |
| queue 与共享变量区别 | queue 明确复制、顺序和阻塞；共享变量需自建同步协议 | 最新值为何用长度1覆盖 | P1/P2 mailbox |
| 实时等于快吗 | 不是，实时强调最坏时间可预测和截止期满足 | Linux 是实时系统吗 | STM32 与 Linux 对比 |
| Tick 回绕如何处理 | 对无符号计数做差并限制超时时间小于半范围 | 绝对截止为何错 | P2 FSM 测试 |
| FSM 为什么优于 delay | 每步短执行，可响应事件、超时与停止 | 状态爆炸怎么办 | P2 控制任务 |
| watchdog 怎么设计 | 喂狗条件应代表关键任务都健康，而非任意循环仍运行 | 谁来汇总心跳 | P1/P2 B级迁移 |

## 4. Linux 进程、线程与同步

| 正面 | 30 秒答案核心 | 反问 | 项目锚点 |
| --- | --- | --- | --- |
| 进程与线程差异 | 进程隔离地址空间；线程共享进程资源但有独立栈和调度状态 | 崩溃影响范围 | P3/P4 架构 |
| 用户态到内核态怎么切换 | 系统调用/异常进入内核，校验参数后执行并返回 | 切换等于进程切换吗 | socket/read/epoll |
| 条件变量为何要循环等待 | 唤醒不等于条件成立，存在虚假唤醒和竞争 | notify 是否必须持锁 | P3 BoundedQueue |
| 死锁四条件 | 互斥、持有等待、不可剥夺、循环等待 | 项目怎么预防 | P3/P4 锁序与短临界区 |
| detach 与 join | detach 失去汇合点；可控资源生命周期通常应 join | 阻塞 read 如何退出 | P4 stop 顺序 |
| 快照模式是什么 | 锁内复制一致状态，锁外耗时处理 | 复制开销太大怎么办 | P4 latest() |
| false sharing 是什么 | 不同变量共享 cache line 导致一致性流量 | 项目证明遇到了吗 | RELATED，不声称已遇到 |
| 虚拟内存价值 | 隔离、统一地址、按需映射和共享；缺页有成本 | mmap 与 read 取舍 | 03章 B级 |
| fd 是什么 | 进程 fd 表索引，指向打开文件描述和底层对象 | dup 后偏移量是否共享 | P3/P5 |
| 如何优雅退出多线程 | 通知停止、解除阻塞、join、释放资源 | 信号处理器能否直接 join | P3/P4/P5 |

## 5. Linux I/O 与网络

| 正面 | 30 秒答案核心 | 反问 | 项目锚点 |
| --- | --- | --- | --- |
| TCP 与 UDP 怎么选 | TCP 有序可靠字节流；UDP 保留报文边界、低开销但需自管丢包乱序 | 雷达为何常用 UDP | P3 |
| TCP 粘包是什么 | TCP 没有消息边界，接收端必须按长度/分隔符/固定帧解析 | 一次 recv 为何不等于一包 | 04章 |
| select/poll/epoll 区别 | fd 表达和就绪获取方式不同；epoll 避免每轮复制/扫描全部集合 | epoll 一定更快吗 | P3/P5 |
| LT 与 ET | LT 未处理完会继续提示；ET 只在状态变化提示，通常非阻塞读到 EAGAIN | 漏读会怎样 | P3/P5 |
| epoll 通知了什么 | fd 就绪，不保证业务帧完整，也不保证后续调用必成功 | 半帧怎么办 | P5 缓冲解析 |
| 非阻塞 I/O 如何处理 | 接受 EAGAIN，维护状态和缓冲，等下一事件 | busy loop 如何避免 | P3/P5 |
| timerfd 的价值 | 把定时器变成 fd 并入事件循环，可读出累计到期次数 | 与 sleep 区别 | P5 conditiond |
| signalfd 的价值 | 屏蔽普通异步处理，把选定信号转换为可读事件 | 哪些信号不能捕获 | P5 conditiond |
| 字节序为何重要 | 多字节整数跨主机传输需约定顺序；网络通常大端 | 浮点怎么传 | P3 数据协议 |
| 退避为何要上限 | 避免故障时忙重试，也限制恢复等待；可加 jitter 防同步风暴 | 成功后怎么处理 | P4 |

## 6. Linux 驱动与 IIO

| 正面 | 30 秒答案核心 | 反问 | 项目锚点 |
| --- | --- | --- | --- |
| DTS 到 probe 的链路 | DT 节点实例化设备，与驱动 compatible 匹配后总线调用 probe | compatible 错会怎样 | P5 |

| 为什么用 IIO | 传感器有标准 channel、scale、buffer、trigger 和用户态接口 | misc 字符设备何时更合适 | P5 |
| hrtimer 能否直接 SPI | timer 回调是原子上下文，不应调用可睡眠 SPI 传输 | 正确路径是什么 | P5 trigger poll |

## 7. 高频辨析表

| 容易混淆 | 正确边界 |
| --- | --- |
| `volatile` vs atomic | 前者是访问可观察性；后者才提供原子操作和内存序语义 |
| atomic vs mutex | atomic 适合单对象状态；mutex 可保护跨字段不变量和复合操作 |
| mutex vs binary semaphore | mutex 有所有权语义，常带优先级继承；binary semaphore 更像事件/令牌 |
| queue vs mailbox | queue 保存多个按序元素；mailbox 强调最新状态，可用长度 1 覆盖实现 |
| 实时 vs 高吞吐 | 实时看最坏延迟与截止期；高吞吐看单位时间处理量 |
| 并发 vs 并行 | 并发是任务交错推进；并行是在多个执行单元同时运行 |
| 线程安全 vs 可重入 | 线程安全可依赖锁；可重入要求并发/递归进入也不依赖不安全共享状态 |
| 阻塞 vs 同步 | 阻塞描述等待时线程状态；同步描述协调关系，两者不是同一维度 |
| epoll ET vs 非阻塞 | ET 通常必须配合非阻塞并读到 EAGAIN；二者概念不同 |
| 编译通过 vs 运行通过 | 编译证明接口与语法；运行还涉及配置、环境、时序与数据 |
| HOST vs CROSS | HOST 在当前机器执行；CROSS 只由目标工具链生成产物 |
| CROSS vs HIL | CROSS 不接触真实硬件；HIL 必须记录板卡、镜像、操作和结果 |
| 驱动 vs 用户态算法 | 驱动负责硬件机制和标准接口；算法策略尽量留在可测试用户态 |
| sysfs vs 字符设备 | sysfs 面向少量属性；字符设备适合流式/二进制数据和标准操作 |
| DTS vs 驱动代码 | DTS 描述板级实例和资源；驱动实现同类设备的通用行为 |

## 8. 五项目 30 秒卡

### P1 手持体温检测仪

多源输入需要满足身份、测温质量和时效条件才能形成一次测量。重构把 ISR 限制为采集/通知，任务间通过 queue 与 mutex 协作，持久化记录带版本和 CRC。Host 测试覆盖融合策略和 CRC 损坏；外设时序、Flash 掉电一致性仍需上板。

### P2 智能送药小车

核心难点是视觉帧、称重和执行器不能彼此阻塞。我使用单写者控制任务驱动非阻塞 FSM，ISR 只收帧并通知，最新传感器状态用邮箱式覆盖，超时按无符号 Tick 差值处理。Host 测试覆盖状态迁移和回绕，电机参数仍需实车标定。

### P3 三维 LiDAR 感知

UDP/PCAP 输入进入有界队列和并行处理流水线。设计明确容量、过载和 EOF 语义，socket/epoll 通过 RAII 管理；退出按停止、关闭、唤醒、join、释放执行。宿主测试证明队列协议，真实设备吞吐和 ROS/PCL 集成仍需实机。

### P4 多源光电数据融合

ROS、Qt、串口和视频线程之间最重要的是共享状态和生命周期。单状态使用 atomic，复合结果使用 mutex 保护并复制快照，连接失败做有上限退避，所有工作线程可停止并 join。源码和局部 Host 测试支持这些结论，完整依赖集成不冒充已验证。

### P5 I.MX6ULL 状态监测器

ICM20608 由 DTS 实例化，SPI 驱动用 regmap 和 IIO 暴露通道与缓冲；hrtimer 只触发线程化采样，不在原子上下文做 SPI。用户态以 epoll 统一处理 IIO、timerfd 和 signalfd，算法可独立回放。Host、ARM 用户态和 vendor 驱动对象已验证，模块加载与实板数据仍是 TODO-HIL。

## 9. 追问失分警报

听到自己说出以下句子时，应立即纠正：

- “volatile 可以保证多线程同步。”
- “epoll 一定比 select 快。”
- “UDP 比 TCP 快，所以选 UDP。”
- “用了 mutex 就不会死锁。”
- “用了智能指针就不会泄漏。”
- “交叉编译成功说明能在板子上运行。”
- “设备树加载驱动。”——应说明匹配、设备实例和总线 probe 链路。
- “中断不能调用任何函数。”——应说只能调用满足上下文约束的函数。
- “实时系统就是运行速度快。”
- “一次 read 就是一帧数据。”
- “我做过完整驱动项目。”——当前应准确说明教学项目来源和 HIL 状态。
